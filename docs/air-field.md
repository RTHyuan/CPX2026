# iPhone Air 开发与现场验收 · 2026-11-22

## 版本与复现

本地标签 `pathsense-pre-model-disable-20261122` 指向 `4e46f61`。`main` 保留这个节点。`git log --oneline --all --decorate` 可查看历史。要同时查看旧版，可运行 `git worktree add --detach ../CPX26-baseline pathsense-pre-model-disable-20261122`。历史实验的模型、训练数据和源码仍在仓库。当前 App 用 Apple Vision 和确定性规则识别标牌。

在 Mac 运行 `swift test`、`Scripts/verify-vision.sh`、`python3 -m unittest discover -s Proxy` 即可分别复现核心、像素和代理回归。iPhone Air 模拟器测试使用 README 中的 `xcodebuild test` 命令。使用干净构建目录，在生成安装包后运行 `python3 Scripts/check-app-bundle.py <PathSense.app 路径>`。它检查应用标识、摄像头/麦克风/听写/本地网络权限文案、可执行文件和模型资源。

## 实机怎么测

1. 用数据线连接 Air，解锁并允许「信任这台电脑」。在 Xcode 的 Devices and Simulators 中确认这台实体 Air 可以供开发使用。选择 PathSense scheme、实体 Air 和开发签名后按 Run。
2. 首次测试用首页「说出目的地」说「带我去教室门口」。重听一次，确认普通话、音量和朝向提示。摸到方向对准的一下轻震后，再测试遇到障碍的两下强震。人和手机都稳定时才点「手机已朝向身体前方」。
3. 记录相机拒绝权限时的说明、重新授权后的扫描、暂停时相机收起、继续后重新识别，以及语音改口。需要测试云端时按 README 配对。代理认证、响应帧号和实际指导分别记录。
4. 仅执行相机与输出诊断时，可以从 Xcode 以参数 `--pathsense-device-check` 启动 Debug 版。`Documents/PathSense-device-check.json` 包含本轮时间、计数和回调。`freshSession` 要求恢复后的新会话实际产出观察。普通启动按用户操作运行。

## 平坦通道上的六轮记录

陪同者先独立检查整段地面，标记要核对的门与相邻门。在路径之外标记测量位置。步行者继续使用日常出行辅助。台阶场景从安全站位观察。

| 场景 | 观察重点 | 实机结果 |
|---|---|---|
| 背对门，从展位出发 | 找到侧过道，记录是否在同一位置转第二圈及到门耗时 | 待测 |
| 移椅后重新开始 | 下一段方向随现场变化，旧障碍位置重新复核 | 待测 |
| 陪同者进入过道再退出 | 记录首次进入有效画面、开始播报、身体停下三个时刻。绕行后由陪同者核对门身份 | 待测 |
| 延迟云端，原地转手机 | 目标先在右 30°，向右转 60° 后提示改为左 30°。横移后重新核对 | 待测 |
| 遮挡、断网、追踪中断 | 逐项记录等待提示与恢复后的首次有效观察 | 待测 |
| 站定看疑似下行台阶 | 及时提示停步、请人协助或改找平坦通道 | 待测 |

每一轮记录起始朝向、耗时、同站完整转圈数、人工核对门身份、漏报与误报、是否人工结束。打开帮助页可分享当次匿名计时。`activeSeconds` 排除暂停时间，`finished - started` 包含暂停时间。`identityContinuous=false` 表示坐标系曾重建，前后门编号需要人工核对。`detectedAt` 是本机近场判为危险的帧时间，`speechStarted` 是系统合成开始回调。完整的入镜至出声时间要与陪同者的独立视频或人工录时对照。

## 已观察到的边界

- 合成像素回放中，平坦地面的高对比度横条纹触发了疑似台阶停步。真实低凳、细椅腿、透明玻璃和深色织物的漏报次数待实走登记。
- 先前的 Air 诊断记录了 207 个位姿、31 次近场结果、4 次关键观察。普通话开始和结束均收到回调。触觉适配器记录 `alignment`、`stop-first`、`stop-second`。该轮的暂停清空与新会话检查均为 `false`。本轮诊断已改为等待相机和观察实际就绪后再测。
- 参与者实际听感、震感、说话识别和陪同走完全程均待实机记录。回放专用的受控绕行和自动到门测试由模拟器测试包提供输入。
