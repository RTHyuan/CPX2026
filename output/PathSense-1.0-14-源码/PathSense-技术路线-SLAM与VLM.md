# PathSense 技术路线：双模式导航 / 两图体系 / 反应式避障 / VLM 与其他 API 分工

版本 v4 · 2026-11-21 · 简体表述

本轮相对 v3 的实质变化：
1. 演示机确认可用带深度传感器的 Pro 机型，避障主方案改为深度优先，纯视觉降级为备用路径；
2. 避障结构从「检测障碍后报警」改为「连续输出可通行朝向」，与人作为执行者的反应延迟匹配；
3. 对外安全承诺改为**单向保底承诺**：只要摄像头看到就撞不到，采用保守策略；
4. 方向指令量化到 15 度档，固定句式因此可实现；
5. **房间内避障确认为本项目最主要功能**，在线局部图从辅助层升为主投资项。

---

## 1 一句话分工

**矢量先验图回答「去哪儿」，端侧在线图回答「脚下能不能过」，VLM 与 LLM 回答「这是什么、这里是什么地方」。**

硬约束三条：
- **安全相关判定绝不经过网络往返**；
- **VLM 与 LLM 输出永不作为几何真值**；
- **安全承诺是单向的**：看见必避，不承诺未看见一定安全。

| 层 | 职责 | 位置 | 循环周期 | 断网 |
|---|---|---|---|---|
| 反应层 | 深度与视觉几何 → 可通行朝向 → 方向指令 | 端侧 | 100–200 ms | 必须可用 |
| 定位层 | 视觉惯性位姿、地图约束、楼层判定、房间内相对位姿 | 端侧 | 100 ms | 必须可用 |
| 语义层 | 标识理解、空间实体分类、图纸矢量化、地点解释 | 云端为主，端侧兜底 | 秒级，异步 | 降级到规则 |

## 2 避障主方案：反应层（本项目最主要功能）

### 2.1 为什么不是「检测到障碍就报警」

使用者本身就是执行者。完整反应链路是：

```
系统检测 → 生成语音 → 使用者听到 → 理解 → 决定动作 → 开始移动
```

这条链路实际耗时 0.8–1.5 秒。以 0.8 米每秒行走，使用者会在听到警告后又前进 0.6–1.2 米。若按 1.2 米每秒，前进 1.0–1.8 米。

因此**报警式结构不成立**。正确结构是**每帧连续输出「朝哪个方向可以走」**，把决策提前到障碍进入危险距离之前。这与清扫机器人反应层的做法一致，也是唯一能兑现单向保底承诺的架构。

### 2.2 反应层管线

```
深度图 或 单目图像
        ↓
地面平面估计（重力对齐，来自惯性器件）
        ↓
极坐标占据直方图（以使用者为中心，按角度分扇区，记录最近障碍距离）
        ↓
扇区评分：净空 − 转弯代价 − 历史一致性惩罚
        ↓
选出最优可通行扇区 → 量化到 15 度档 → 方向指令
```

三类输入可替换，接口不变：

| 模式 | 输入 | 距离精度 | 适用场景 | 失效条件 |
|---|---|---|---|---|
| 主方案 | 深度传感器 | 米级，3–5 米内可靠 | 房间内、走廊 | 玻璃、镜面、黑色织物、强光、远距离 |
| 降级一 | 单目地面反向投影 | 近似米级，平地有效 | 平地、门口、走廊 | 坡度、台阶、远距离分辨率衰减 |
| 降级二 | 单目语义检测 + 落地投影 | 仅方位，不给距离 | 紧急兜底 | 细杆、低矮物、透明物 |

**地面反向投影**是纯视觉主力的可行做法：用惯性器件给出的俯仰与横滚角把地面标定成鸟瞰图，凡偏离地平面的像素即判为障碍。平地有效、无需深度、近似米制——这正是纯视觉清扫机器人的核心手段。它的失效条件（坡度、台阶、远距离）与深度的强项互补，因此两种模式并存而不是互相替代。

### 2.3 保守策略的具体含义

保守策略不是「更谨慎地判断」，而是**把不确定性一律归为不可通行**：

1. 深度缺失或置信度低的扇区 → 视为占用；
2. 未标定的远处 → 视为未知，不进入评分；
3. 使用者朝向未更新 → 冻结上一条指令，不擅自改写方向；
4. 连续三帧结论冲突 → 输出「停下」，而非平均；
5. 地面平面估计跳变 → 整帧丢弃，不复用历史栅格。

这条纪律的代价是**通行效率低**，换来的是单向承诺可兑现。

### 2.4 方向量化与 30 度容差

输出量化到 **15 度档位**，共 9 档（左 60 度至右 60 度，每 15 度一档，另含「停下」）。

量化误差最大 ±7.5 度，叠加使用者执行误差与朝向估计误差后仍在 30 度容差内。量化同时使固定句式可实现——档位是有限集合，每档对应一句固定文本。

### 2.5 速度与净空的关系（写进演示台词）

| 房间内行走速度 | 所需净空 | 反应层起始修正距离 | 激光雷达 5 米量程是否够 |
|---|---|---|---|
| 0.6 米每秒 | 1.0–1.5 米 | 2.0 米 | 充裕 |
| 0.9 米每秒 | 1.5–2.0 米 | 2.5 米 | 够 |
| 1.2 米每秒 | 2.5–3.0 米 | 3.5 米 | 勉强，且指令跟随变差 |

因此房间内**引导慢速行走**，这不是能力缺陷，而是安全设计的组成部分。

### 2.6 向下持机是硬性前提

iPhone 的深度传感器有效量程约 5 米，且**向下台阶属于负障碍**——平举手机时不在视野内。

因此房间内与楼梯附近**必须**要求持机向下倾斜 30–45 度，让地面与台阶边缘进入画面。这是用户操作规范与演示台词的一部分，不是可选建议。

## 3 双模式（谁提供路线）

两种模式共用同一套反应层与定位层，只在「谁提供目标方向」上不同。

| | 模式 A：无先验图 | 模式 B：有先验图 |
|---|---|---|
| 触发 | 未加载该楼栋矢量图，或配准失败 | 已加载且完成粗配准 |
| 路线来源 | VLM 与 LLM 依据现场读到的房号与标识做序数推理 | 矢量图上的几何路径 + 派生拓扑图 |
| 空间表达 | 相对、序数（「往编号变大的一侧走」） | 绝对、米制（「前方 18 米右转」） |
| 定位要求 | 只需走廊方向与相对进度 | 需大图坐标系位姿 |
| 主要失败模式 | 编号不单调、分叉无编号 | 配准丢失、图与现场不符 |
| 演示角色 | 泛化能力证据 | 完成度证据 |

**两种模式都始终叠加反应层**：路线层给方向，反应层可否决它。路线层说「直行」，而正前方 1.5 米有椅子时，反应层输出「向左 30 度」，且优先级更高。

### 3.1 无先验图的序数推理链

```
视野内标识与门牌 → 规范化房号序列（如 301、303、305）
        ↓
当场推断编号走向（递增或递减）与奇偶侧
        ↓
LLM 输出一段可行走指令 + 依据 + 置信度
        ↓
端侧执行，见到新证据即重算
```

工程纪律：
- **编号走向不是常数**。回字形、双面走廊、奇数一侧偶数一侧都常见，必须由当场观测的相邻两块牌推断，不得写死「递增就在前方」。
- 一次只给**一段**指令，不做长距离序数外推。
- 分叉且无编号时**不猜**，改为请求确认。
- 该模式不产生几何坐标，只记录观测到的编号顺序作为抽象约束。

### 3.2 有先验图的五段任务链

| 段 | 任务 | 依赖 | 优先级 |
|---|---|---|---|
| 1 出门 | 房间内到走廊，避开门内家具与椅子 | 反应层 | **最高（房间内避障是主功能）** |
| 2 进入走廊 | 确定所在走廊段与朝向 | 走廊约束定位 + 锚点 | 高 |
| 3 走廊行走 | 沿矢量路径推进，避让行人与堆物 | 路径 + 反应层 | 高 |
| 4 找到教室 | 看到目标房号并确认 | 标识锚点 | 高 |
| 5 进门 | 门洞定位 + 门内避障 | 反应层 + 门洞属性 | **最高（与第 1 段同类）** |

第 1 段与第 5 段是同一类问题：**小空间、无先验几何、障碍密集**。这是本项目的主投资项，也是深度传感器价值最大的地方。

## 4 大图规格（矢量先验图）

- 坐标系：楼栋局部东北天坐标，z 轴即楼层，单位米，含重力对齐。
- 几何图元：墙段（线段与厚度）、门洞（位置、宽度、开合方向）、走廊中心线、房间多边形、楼梯与电梯连通件、楼栋外轮廓与总长宽。
- 属性：房号、房间类型、可见标识文本、无障碍属性、**房间内是否含台阶**。
- 派生索引：由自由空间骨架生成拓扑图（节点＝房间、走廊交点、设施；边＝可达性、步数、门与楼梯）。几何图为真值，拓扑图仅为查询索引。

三个来源合成一张图：

| 来源 | 用途 | 产出 |
|---|---|---|
| 路演前预扫描（激光雷达、视觉、手机内置惯性器件） | 主骨架、绝对尺度、楼栋长宽 | 点云 → 墙体与地面 → 矢量化 |
| 楼层平面图与课表导入 | 房间语义、编号、缺失墙体补全 | 图像 → 矢量化 → 与点云配准 |
| 现场增量 | 修正墙体偏差、补门与标识、新增设施、**记录房间内固定障碍** | 抽象约束，非原始地图 |

融合纪律：
- 现场增量只上报**抽象约束**（锚点、规范化房号、门洞观测、墙体线段、固定障碍位置与类别），**绝不上报端侧在线图**。
- 多会话观测做一致性投票；冲突进入待确认队列，不自动覆盖先验。
- 每次融合产生带版本号的图快照，端侧按版本号判断是否刷新缓存。
- **房间内固定障碍可回写大图**，这是本项目独有的增量价值：第一次进某房间走过的路，第二次可直接用。

本期范围：**演示楼栋的一层加一部楼梯**。扩展到全校区是架构上的容量设计，不是本期已完成内容。

## 5 在线局部图规格（端侧）

| 项 | 规定 |
|---|---|
| 表示 | 2D 占据栅格（可通行、不可通行、未知）+ 近场障碍几何 + 极坐标最近障碍直方图 |
| 尺度 | 房间内近似米制（深度传感器提供），走廊内随视觉惯性位姿累积 |
| 生命周期 | 会话结束后留本机，不销毁、不导出、不上传；清理策略另行确定 |
| 作用域 | 仅本地反应层、定位与锚点关联；不跨设备共享 |
| 精度目标 | 3–5 米内相对误差小于 0.5 米 |

**主次关系已调整**：房间内避障是主功能，因此在线图的任务中，「大图未建模的家具、椅子、桌角、台阶」是**第一优先**，不再只是「补充」。

## 6 端侧定位管线

```
相机帧 ─┬─ 平台视觉惯性位姿（六自由度，重力与尺度收敛）
        ├─ 地面平面与楼层判定
        ├─ 关键帧文字检测与识别（低频，非每帧）
        ├─ 深度图或单目地面反向投影
        └─ 近场障碍检测与扇区直方图

位姿 ──→ 地图约束状态估计 ──→ 大图坐标系位姿 ──→ 在线栅格 ──→ 拓扑路由
             ↑                                              ↓
      标识锚点 / 门洞 / 走廊轴线                    反应层方向指令
```

### 6.1 位姿主干

使用平台级视觉惯性里程计作为位姿骨架，不自研后端优化。自研集中在**地图约束融合、锚点纠偏、反应层、在线图层**。理由：24 小时内自研视觉惯性里程计必然失败，且误差特性无法向评委解释。

### 6.2 走廊约束定位

不放开六自由度自由漂移，把状态压到走廊约束下的低维流形：楼层已知则 z 与重力锁定；走廊内状态降为「沿走廊轴线进度 s + 横向偏移 d + 航向偏差 Δθ」，用走廊轴线拟合、门洞侧向观测、标识锚点做观测更新。

走廊是一维结构，此约束把航向漂移从自由累积变成被墙体吸住，是普通手机条件下最可靠的纠偏手段。

### 6.3 锚点

- 类型：房号牌、楼层索引、电梯与出口标识、楼梯标识、门框、消防疏散图。
- 存储：规范化文本、端侧位姿、置信度、对应大图节点编号。
- 三重作用：位姿纠偏、在线图与大图配准、方向指令的落点。
- 多次观测取加权平均；低置信度只记日志不入图。

### 6.4 两图配准

初始由用户选楼层与起点节点（或一次标识扫描）得到粗变换；运行中由走廊轴线对齐与锚点迭代校正，得到在线图到大图的刚体变换（仅平移与航向）。该变换在端侧计算与保存，上行只有抽象约束。

## 7 VLM 与其他 API 的类型分工

| 类型 | 输入 → 输出 | 侧 | 用途 | 断网降级 |
|---|---|---|---|---|
| 端侧检测与识别运行时 | 帧 → 文本标记、框、类别 | 端 | 文字识别、家具与行人检测、台阶检测 | 必须原生可用 |
| 端侧位姿运行时 | 帧与惯性数据 → 六自由度位姿 | 端 | 位姿主干 | 必须原生可用 |
| 深度或几何估计运行时 | 帧 → 深度图或地面反向投影 | 端 | 反应层输入 | 必须原生可用 |
| 多模态结构化抽取 | 关键帧与文本标记 → 受限模式 JSON | 云 | 空间实体分类、房号规范化、标识语义、相邻关系候选、**房间内固定障碍入库** | 本地存帧，排队重试 |
| 图纸与文档解析 | 平面图或课表 → 墙体与房间与编号的矢量初稿 | 云，离线一次性 | 矢量化与房间清单 | 手工录入种子图 |
| 推理与规划 | 子图或序数观测 + 目标 → 节点序列或一段指令 + 依据 | 云，低频 | 有图时路由、无图时序数推理 | 端侧图搜索，或退化为固定规则 |
| 语音合成与识别 | 文本 ↔ 语音 | 端优先，云兜底 | 交互 | 系统语音合成 |
| 向量检索与嵌入 | 地标描述符 → 最近节点候选 | 云或端 | 回环匹配 | 端侧本地索引 |
| 图像生成 | 提示词 → 图 | 云 | 仅海报与演示素材 | 与导航回路完全隔离 |

调用纪律：
1. 只对**关键帧**调用云端（新标识、位姿置信度骤降、在线图与大图冲突、进入新房间）。
2. 感知哈希去重与结果缓存，同一节点不重复付费。
3. 所有云端输出过模式校验与置信度门限，低置信度不入图不入库只入日志。
4. 冲突裁决：**精确文本标记（房号）以端侧为准**，VLM 只裁决语义类别与相邻关系。

禁止项：
- VLM 或 LLM 输出坐标、距离、方向角度；
- VLM 或 LLM 参与避障决策；
- 端侧在线图或原始相机画面上传；
- 云端结果被当作几何真值写入矢量图。

## 8 指令输出层

本轮确定为**纯固定句式**，模型润色留作后续改进。收益有三：完全离线、测试用例可写成确定字符串比对、说法前后一致不产生语义漂移。

**语音后端采用系统语音合成，并通过抽象接口隔离。** 不预录音频，改用 iPhone 系统语音合成朗读固定句式；同时预留一个文转语音模型的替换接口，后续接云端语音模型只需换实现，不改调用方。接口形态：

```
SpeechOut.speak(text, priority, interrupt) → 异步返回「播报开始」与「播报结束」事件
```

`priority` 用于让「停下」抢占正在播报的普通提示；`interrupt` 用于目标切换或任务中止时清空待播队列。两个事件都要可观测，因为第 10 节的时延验收需要「播报开始」时间戳。

代价与对策：系统语音合成从提交文本到出声约 100–300 毫秒，比预录音频慢但要远小于 500 毫秒的时延门槛，因此**仍满足验收**。真正需要控制的是**播报时长**——固定句式必须短，安全类指令控制在四到六字，避免一句话还没念完方向已经变了。

另需注意：VoiceOver 开启时不得让两条语音通道叠读，安全指令走单一通道播报。

### 8.1 指令分级与优先级

| 优先级 | 级别 | 触发 | 例句 | 频率 |
|---:|---|---|---|---|
| 1 | 停止 | 连续三帧冲突，或前方净空低于安全阈值 | 「停下」 | 状态变化时 |
| 2 | 避障转向 | 反应层最优扇区偏离当前朝向超过一档 | 「向左三十度」「向右十五度」 | 每档变化一次 |
| 3 | 障碍存在 | 障碍进入 1.5 米且当前方向不改 | 「前方有障碍」 | 每次进入一次 |
| 4 | 路线转向 | 距拓扑节点小于 2 米 | 「前方两米右转」 | 每节点一次 |
| 5 | 地标 | 命中锚点 | 「左手边是三零五」 | 每锚点一次 |
| 6 | 到达 | 距目标节点小于 1.5 米 | 「三零五到了，门在左手边」 | 一次 |
| 7 | 不确定 | 位姿置信度低或配准丢失 | 「我暂时不确定位置，请站定两秒」 | 一次，不重复 |
| 8 | 直行确认 | 连续直行超过 8 米无观测 | 「继续直行」 | 低频 |

**反应层优先级高于路线层**：路线说直行而正前方有障碍时，以避障指令为准。

### 8.2 语音链路预算（必须实测的数值）

| 环节 | 典型耗时 | 备注 |
|---|---|---|
| 深度或视觉推理 | 30–80 ms | 端侧，按机型实测 |
| 扇区评分与选向 | 小于 5 ms | 纯数值计算 |
| 系统语音合成启动 | 100–300 ms | 首次调用可能更慢，须预热 |
| 语音播报时长 | 约 0.8–1.2 秒（四到六字） | 与字数近似成正比 |
| **端到端（到播报开始）** | **约 150–400 ms** | 验收门槛 500 ms，需留余量 |

统一说法：**「指令在 X 毫秒内开始播报，完整播报在 Y 秒内结束」**，不混用「响应时间」这类模糊表述。

必须做的两件优化：
1. **预热语音引擎**：进入房间模式时先播一次空字符串或极短音节，把首次合成的长延迟移出关键路径。
2. **抢占与截断**：新方向指令到达时立即取消正在播报的旧指令，避免「向左三十度」念到一半已经该向右。

### 8.3 追问应答

固定句式无法回答「为什么让我往左」。因此增设一张**固定应答表**（约 10 条），而不是让模型自由回答：例如「为什么往左」→「左边一米内没有障碍，右边有椅子」。

## 8A 固定障碍回写机制

房间内探测到的固定障碍回写大图，这是本项目「越用越好」的增量价值来源。规则必须写死，否则会污染大图。

### 8A.1 什么算固定障碍

| 判据 | 处理 |
|---|---|
| 同一位置连续三次以上观测命中，且类别一致 | 回写 |
| 两次观测之间位移小于 0.3 米 | 视为同一障碍，合并计数 |
| 类别不一致（一次判椅子一次判桌子） | 不回写，记日志 |
| 曾在原地消失又出现 | 不回写，标为临时物 |
| 检出类别属于行人、宠物、活动展架 | **永不回写** |

### 8A.2 回写内容

只写抽象约束，不写原始点云或栅格：

```
FixedObstacle = roomID + 相对房间中心位姿(2D) + 类别 + 包围盒尺寸估计 + 观测次数 + 最后观测时间 + 置信度
```

### 8A.3 使用与失效

- 端侧按房间加载该房间的固定障碍列表，作为反应层的**先验占用**，与实时观测同等对待。
- 先验占用**不覆盖**实时观测：若实时观测显示该处已空，以实时为准，并降低该条目的置信度。
- 置信度衰减：连续两次进入该房间都未观测到该障碍，置信度下降；降至阈值以下则从大图移除。
- 回写走云端结构化抽取路径，与标识锚点同一通道、同一审核队列。

## 9 数据契约

```
Pose      = frameID + t + T_world_local(六自由度) + confidence + source
Anchor    = id + kind + text_norm + T_world(六自由度) + conf + nodeID
OnlineGrid= origin + resolution + cells(occupancy ∈ {free, occupied, unknown}) + version
SectorMap = t + bins[角度 → 最近障碍距离] + confidence
Directive = level + quantizedHeading + slots + evidenceID + cooldownKey
```

- `Pose` 只追加不修改，位姿修正以新记录追加。
- `Anchor` 是两图唯一合法桥接件。
- `OnlineGrid` 与 `SectorMap` 永不出设备。
- `Directive` 必须可追溯到触发它的证据，便于回归测试。

## 10 安全验收协议（可证伪）

对外承诺是**单向保底承诺**：**只要摄像头看到就撞不到**。因此验收也必须是单向的——测「看到时是否避开」，不测「是否撞上」，因为漏检在物理上无法归零。

### 10.1 必测的四个量

| 指标 | 定义 | 验收门槛 |
|---|---|---|
| 看见必避率 | 障碍处于视野且距离大于 2 米时，系统是否在进入 1 米前给出正确方向 | **100%**，人工复核每一帧漏报 |
| 指令时延 | 障碍首次进入 2 米到方向指令**开始播报** | **小于 500 ms** |
| 方向正确率 | 输出的 15 度档位与人工判定最优档一致或在相邻一档内 | 大于 90% |
| 抖动率 | 相邻两帧方向指令来回跳变的次数 | 每 10 秒少于 2 次 |

**关于 100% 的门槛，必须写清成立条件**，否则是不可兑现的承诺：

100% 只在「障碍已被检测器看见」的集合上计算。检测失败（玻璃、镜面、细杆、黑色织物）的样本不计入分母，而是单独列入 10.2 的失败场景表并如实报告。这正是**单向保底承诺**的含义——保证看见必避，不保证未看见一定安全。评审若追问，回答：「100% 的分母是检测成功集合，检测漏报我们有单独的清单。」

时延门槛 500 毫秒对应的是**开始播报**，不是播报结束。以 0.6 米每秒行走，500 毫秒对应前进 0.3 米，仍在 1.5 米安全净空内。

### 10.2 必测的失败场景（诚实列出）

| 场景 | 预期行为 | 是否算通过 |
|---|---|---|
| 玻璃门、镜面 | 可能漏检 | 通过条件：不误报为可通行；允许输出「停下」 |
| 细杆、椅子腿 | 可能漏检 | 通过条件：若漏检须在报告中列出，不计入看见必避率 |
| 黑色织物、深色地毯 | 深度可能失效 | 通过条件：confidence 低时按保守策略视为占用 |
| 向下台阶 | 需持机下倾才可见 | 通过条件：平举时须输出「请向下倾斜手机」 |
| 强光、逆光 | 深度可能失效 | 通过条件：降级到地面反向投影或停止 |
| 行人突然进入 | 反应层需修正 | 通过条件：1.5 米外给出方向 |

### 10.3 演示口径

必须说：**「它保证看见的障碍一定避开，采用保守策略，看不见的情况我们会明确告知用户。」**

不能说：**「它不会撞到东西。」** —— 这既不可证伪，也不符合单目与深度传感器的真实能力边界。

## 12 参考实现核实结果

| 参考 | 实际情况 | 可用部分 | 不可用部分 |
|---|---|---|---|
| `NiteeshL/NavAIgate` | Kotlin 安卓应用，每帧送云端多模态模型，约每 4 秒返回 3–4 句自然语言再播报 | 交互循环结构、无障碍界面、提示词写法 | **不能作安全层**：4 秒反馈对应前进 4.8 米；仓库含明文 API Key，禁止照抄 |
